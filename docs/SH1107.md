# SH1107: SPI/I2C driver, diagnostic and 128x64 renderer

Target: Waveshare **1.3inch OLED Module (C), SKU 18179**, white monochrome,
native 64x128 pixels. The diagnostic supports both SPI and I2C.
The player service still uses the SSD1327. The SH1107 profile remains
`driver_ready=False` until runtime integration and physical validation.

## Implementation status

- Implemented: SH1107 controller initialization, contrast, full-frame writes,
  blank-before-display-on, display-off on normal exit, software rotation.
- Implemented: separate SPI and I2C transports, deferred hardware imports,
  configurable control pins, CE0/CE1, and offline PNG previews.
- Implemented: hardware-independent `mono1-vlsb` GraphicFrame validation.
- Implemented: `CompactRenderer` (`sonos_ui/compact_graphic.py`), drawing the
  common semantic screens on a monochrome 128x64 canvas, including long-text
  scrolling, for the later player binding.
- SPI hardware confirmed: all patterns display correctly with rotation 270,
  display offset `0x60`, DC on BCM22 and RESET on BCM27 on the project test
  module; these are the diagnostic's defaults.
- Pending: physical I2C and compact UI validation, live player/input binding
  and configuration/service integration.
- Pending separately: SH1107 firmware splash and native shutdown backend.

There is no luma dependency. The controller accepts a transport with `open`,
`reset`, `command(bytes)`, `data(bytes)`, and `close`. Both transports use that
same boundary, including the hardware reset required by this module.

## Wiring (Raspberry Pi, BCM numbering)

Disconnect power before changing wiring. Set the module's **IM selection to 0
for 4-wire SPI**. Supply the module with **3.3 V**.

| Module | Raspberry Pi | Physical header pin |
|---|---|---|
| VCC | 3.3 V | 1 |
| GND | Ground | 6 |
| DIN | BCM10 / MOSI | 19 |
| CLK | BCM11 / SCLK | 23 |
| CS | BCM8 / CE0 | 24 |
| DC | BCM22 (project wiring, diagnostic default) | 15 |
| RST | BCM27 (project wiring, diagnostic default) | 13 |

DC and RST must match the actual wiring; pass `--dc-pin` and `--rst-pin` if the
module is connected differently. The diagnostic
does **not** read `player.toml`. CE1 is supported through `--spi-device 1`
(CS then uses BCM7, physical pin 26). SPI clock defaults to 2 MHz, mode 0.

Do not run two renderers against the same display, chip-select or control pins.
When replacing the existing OLED, first stop its service:

```sh
sudo systemctl stop sonoscdplayer-oled.service
```

Enable SPI in the Raspberry Pi configuration if it is not enabled already.
Required packages: `python3-pil`, `python3-spidev`, `python3-rpi.gpio` (as for the
existing SPI OLED). No I2C package or bus activation is required for this step.

## Offline check

Run from the repository root:

```sh
PYTHONPATH=src python3 -m integrations.outputs.sh1107_test \
  --pattern all --preview-dir /tmp/sh1107-preview
```

This creates grid, checkerboard, text and blank PNGs and prints frame geometry,
byte count and SHA-256. Without both `--gpio` and `--execute`, it never imports
the GPIO/spidev/SMBus libraries or opens hardware. Preview PNGs show the logical
canvas; rotation is applied only when converting to native display bytes.

## Physical test

```sh
sudo env PYTHONPATH=src python3 -m integrations.outputs.sh1107_test \
  --gpio --execute --pattern all --seconds 5
```

The default rotation 270 gives a logical **128x64** canvas as mounted in the
project; `--rotation 90` turns it the other way, `--rotation 0` or `180`
provides 64x128. Rotation
is measured relative to the driver's native SEG/COM mapping; confirm the
physical mounting with the corner markers.

Expected observations:

1. The grid has a continuous one-pixel border on all four edges.
2. The upper-left marker is filled; the lower-right marker is an outline.
3. Checkerboard squares are 8x8, without missing or shifted pages.
4. Text is readable and shows the selected logical dimensions.
5. The final pattern is blank and the driver turns the panel off on exit.

The initial display offset is `0x60` for this 64x128 panel. It is exposed through
`--display-offset 0x60` for explicit diagnostics, not auto-detected. SPI writes
cannot confirm that a panel is connected or displays the intended pixels.
If the border is clipped or wraps, record the rotation, offset and a photo
before changing defaults. A lower SPI clock can be tried with `--spi-hz 1000000`.

Contrast can be checked with `--pattern text --contrast 32` and then `128`.
There is no automatic retry or firmware-splash adoption in this increment.

## Switching the module to I2C

Stop the OLED service, then shut down and disconnect power before changing the
module or wiring:

```sh
sudo systemctl stop sonoscdplayer-oled.service
sudo poweroff
```

Move the module's soldered IM selection from **0 (SPI) to 1 (I2C)** as shown in
the Waveshare module documentation. This is a physical mode selection; the
`--interface` option cannot switch the hardware by itself.

Wire the module for I2C1 as follows (BCM numbering):

| Module | Raspberry Pi / fixed level | Physical header pin |
|---|---|---|
| VCC | 3.3 V | 1 |
| GND | Ground | 6 |
| DIN | BCM2 / SDA1 | 3 |
| CLK | BCM3 / SCL1 | 5 |
| CS | Ground, permanently selected | 6 or another GND |
| DC | Ground, address 0x3C | 6 or another GND |
| RST | BCM27 (example) | 13 |

Disconnect CS and DC from their former SPI GPIO/CE wires before tying them to
ground. The I2C transport drives only RESET; it never drives CS or DC. Tying DC
to 3.3 V instead selects address `0x3D`; use `--i2c-address 0x3D` in that case.
Addresses are seven-bit values, not the shifted write address `0x78`.

After boot, stop the OLED service again. Enable I2C under Interface Options in
`sudo raspi-config` if `/dev/i2c-1` is absent, and reboot if requested. Install
the additional Python binding if needed:

```sh
sudo apt install python3-smbus
sudo systemctl stop sonoscdplayer-oled.service
```

First run a grid-only test with the confirmed orientation:

```sh
sudo env PYTHONPATH=src python3 -m integrations.outputs.sh1107_test \
  --interface i2c --i2c-bus 1 --i2c-address 0x3C \
  --rst-pin 27 --rotation 270 --gpio --execute \
  --pattern grid --seconds 15
```

Then replace `--pattern grid --seconds 15` with `--pattern all --seconds 5`.
Expect the same border, markers, checkerboard and text as on SPI. The text
pattern says `BUS TEST` on both interfaces so the input frame is identical.
Keep `--display-offset 0x60`. A successful I2C transaction alone does not prove
that the image on the panel is correct; physical validation is still pending.

The diagnostic defaults to SPI, RESET BCM27 and rotation 270 (project module).
In I2C mode, omit `--dc-pin`, `--spi-device` and `--spi-hz`; those are rejected
to catch a mixed wiring/configuration early. `--gpio --execute` remain required
because hardware RESET still uses a GPIO.

The I2C bus number and address are configurable. For buses other than the
standard I2C1 wiring above, check that RESET does not overlap the chosen bus
pins. No bus scan, clock reconfiguration, or access to other I2C addresses is
performed. The clock rate is controlled by the Raspberry Pi I2C configuration.

For an offline I2C preview, omit both hardware flags:

```sh
PYTHONPATH=src python3 -m integrations.outputs.sh1107_test \
  --interface i2c --rotation 270 --pattern all \
  --preview-dir /tmp/sh1107-i2c-preview
```

## Frame and command contract

`mono1-vlsb`: a byte stores eight vertical pixels in one column, bit 0 at the
top; bytes progress across columns, followed by the next eight-row page.
Logical frames are exactly 1024 bytes. Dimensions must match the configured
rotation, and their height must be divisible by eight. Invalid frames fail
before a bus write. Thresholding uses luminance >=128 without dithering.

The native buffer is sixteen pages of 64 bytes. Each page write sets page and
column addresses explicitly in SH1107 horizontal addressing mode (`0x20`, a
single-byte command). Initialization uses multiplex 127, start line 0, offset
96, SEG/COM normal mapping and internal DC/DC enabled (`0xAD, 0x81`). Display
RAM is cleared before DISPLAY ON, followed by a 100 ms settling delay.

The I2C transport uses `smbus.SMBus.write_i2c_block_data`: each transaction
starts with control byte `0x00` (commands) or `0x40` (RAM data), followed by up
to 32 payload bytes. I2C-block writes do not add an SMBus count byte. A native
64-byte page is split into two data transactions without changing its address.
Errors propagate without automatic retry, and the bus handle and owned RESET
GPIO are released on exit.

## Tests

```sh
python3 -m pytest tests/test_sh1107.py tests/test_sh1107_i2c.py tests/test_sh1107_preview.py
```

Tests cover vertical packing, page boundaries, all four rotations, invalid
frames/configuration, initialization order, exact page data, contrast, resource
cleanup on errors, and offline execution without hardware imports. I2C tests
also cover control bytes, 32-byte chunk boundaries, address validation, bus
selection and command/data equivalence with SPI across all four patterns.
The physical SPI test is confirmed above; the physical I2C test is pending.
