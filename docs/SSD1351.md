# SSD1351 SPI diagnostic

Target: **Waveshare 1.5inch RGB OLED Module, SKU 14747**, 128x128 pixels,
SSD1351 controller. Branch: `feature/ssd1351-spi`, based on main commit
`76e0858f413c51a09213829cc6082cab6b33df5d`.

## Implementation status

Support includes the live player backend, standalone driver and diagnostic, using
the shared SPI transport and RGB565 packing/rotation shared with the ST7735S.
It supports four rotations, RGB/BGR selection, and the controller's 16-step
master current setting. Each complete frame is 32768 bytes, transferred in
4096-byte chunks. Default SPI speed is 2 MHz, mode 0.

The module diagnostic was successfully tested on hardware on 2026-11-25:
initialization, colors, frame border and brightness sequence worked with the
default RGB/rotation-0 configuration. Initialization, command/data separation,
frame validation, pixel packing, rotations, brightness and cleanup also have
mock tests; the existing ST7735S tests pass after extracting the shared code.

RGB overview/menu previews are hardware-confirmed. The live service now selects
SSD1351 through `[display]`, including real player/menu events and ambient
brightness. Boot and native shutdown builders use the same configuration;
live player operation and the updated startup/shutdown images are hardware-confirmed. See
[Display configuration](DISPLAY_CONFIGURATION.md) for selection and deployment.
The standalone diagnostic does not change the production service/configuration.

## Wiring

Use the module's default **4-wire SPI** configuration (BS0=0). This module does
not provide I2C. It needs seven connections, with no backlight or BUSY pin.

Stop the current display renderer before testing:

```sh
sudo systemctl stop sonoscdplayer-oled.service
```

Power down and disconnect power before swapping the display. Connect by the
labels on the module; check the connector order rather than assuming it matches
the previous display. Use 3.3 V supply and Pi logic for this test.

| Module | Raspberry Pi | Physical header pin |
|---|---|---|
| VCC | 3.3 V | 1 |
| GND | Ground | 6 |
| DIN | BCM10 / MOSI | 19 |
| CLK | BCM11 / SCLK | 23 |
| CS | BCM8 / CE0 | 24 |
| DC | BCM22, revised enclosure wiring | 15 |
| RST | BCM27, revised enclosure wiring | 13 |

**Leave the eighth wire, GPIO9 / physical pin 21, disconnected.** The SSD1351
does not need the ST7735S backlight connection. An existing `no_miso` SPI boot
overlay may remain; neither a backlight option nor `--spi-miso-released` is
needed here. The shared SPI transport owns only DC/RESET and its SPI handle.

Enable SPI on the Pi. Hardware uses Pillow, `spidev` and the same `RPi.GPIO`
binding as the existing display drivers. The commands below explicitly select
DC22/RESET27; the transport defaults are still DC25/RESET24. If CS is actually
connected to CE1, select `--spi-device 1` instead.

After reboot, stop the OLED service again if it started automatically. Keep
other renderers using the same pins stopped throughout the test.

## Run the diagnostic

From the repository root:

```sh
git fetch origin
git switch feature/ssd1351-spi
git pull --ff-only
```

Offline preview (no GPIO/SPI objects are created):

```sh
PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.ssd1351_test \
  --preview-dir /tmp/ssd1351-preview
```

This writes six PNGs and prints nine frame reports, including four brightness
steps. The PNGs show the logical canvas before rotation and do not simulate
electrical brightness or RGB/BGR remapping.

First check the border and orientation:

```sh
sudo env PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.ssd1351_test \
  --gpio --execute --dc-pin 22 --rst-pin 27 \
  --pattern grid --seconds 10
```

Then run the complete sequence:

```sh
sudo env PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.ssd1351_test \
  --gpio --execute --dc-pin 22 --rst-pin 27 \
  --pattern all --seconds 3
```

The sequence lasts about 27 seconds plus initialization. Expected results:

1. Bars, left to right: **red, green, blue, white, cyan, magenta, yellow, black**.
2. Grid: continuous white one-pixel border on all four sides, with red top-left,
   green top-right, blue bottom-left and yellow outline bottom-right markers.
3. Checkerboard: regular 8x8 black/white squares.
4. Text: readable model/dimensions and white `ROT 0` label.
5. Four brightness steps on the same image, increasing through 1, 5, 10, 15.
6. Black frame, followed by controller display-off on exit.

The tested defaults are `--rotation 0 --color-order rgb --brightness 8`.
Use `--rotation 90`, `180` or `270` for the mounting orientation. If red and blue
are exchanged, repeat with `--color-order bgr`. Report the border, color order
and readable rotation before making those hardware-confirmed defaults.

`--brightness 0..15` controls register C7: **0 is 1/16 current, not OFF**;
15 is full master current. The dedicated brightness pattern always sweeps
1, 5, 10 and 15. Display-off is a separate AE command, used during cleanup.
It does not disconnect module power. RAM is cleared before display-on at
initialization. Cleanup closes SPI and releases owned control pins on normal
exit, exceptions and KeyboardInterrupt; it cannot run after SIGKILL/power loss.

## RGB overview and menu preview

These previews reuse the production 128x128 overview renderer and semantic
speaker-selection widgets with the Modern Hi-Fi RGB palette. There is no
grayscale conversion or separate SSD1351 layout. All data is synthetic: this
command does not connect to Sonos/player RPC, react to buttons/the encoder,
or change an actual speaker selection.

After updating the branch, keep the current OLED service stopped and the same
seven-wire connection in place. GPIO9 remains disconnected. The UI needs the
same `fonts-dejavu-core` Unicode font package as the normal overview.

```sh
git pull --ff-only
sudo systemctl stop sonoscdplayer-oled.service
sudo env PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.ssd1351_test \
  --gpio --execute --dc-pin 22 --rst-pin 27 \
  --demo all --seconds 3
```

The approximately 30-second sequence shows three overview states (stopped,
playing, paused), then seven menu scenes. Focus moves through four rooms,
**Übernehmen** and **Zurück**, while Wohnzimmer stays checked. The final scene
previews a second check mark at Küche. Focus, checked state and scrolling of
the three-row window are independent. Long-label marquee animation is not
part of this finite preview; images are rendered before hardware is opened.
No cover file is loaded; the overview uses the normal text-focused layout.

Check text readability, Unicode characters, gold focus background, dark focus
text, independent checkboxes, green progress bar and unclipped status/footer.
At the end the display switches off. Use `--demo overview` (three scenes) or
`--demo menu` (seven scenes) to run them separately; `--seconds 5` gives more
viewing time. Existing rotation, color-order and brightness options also apply.
`--demo` and `--pattern` are mutually exclusive.

Offline PNGs, without SPI/GPIO access:

```sh
PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.ssd1351_test \
  --demo all --preview-dir /tmp/ssd1351-ui-preview
```

The same ten scenes are rendered/validated before any hardware is opened, so
a missing font or rendering error fails before display initialization.

  -s tests/hardware/displays -p 'test_ssd1351*.py'
PYTHONPATH=src python3 -m unittest discover \
  -s tests/hardware/displays -p 'test_st7735s.py'

Verified with Python 3.13: **28 SSD1351 tests and 33 ST7735S tests**, including
production RGB widgets, focus/checkbox independence, offline PNGs, mock SPI demo
execution, invalid CLI combinations and missing-font preflight. Development hosts
may set `SONOSCDPLAYER_TEST_FONT_DIR` to a directory containing the same DejaVu

The RGB overview/menu preview, normal live service and updated startup/shutdown
logo have been physically verified on the project module.

## Primary references

- [Waveshare module documentation and pinout](https://www.waveshare.com/wiki/1.5inch_RGB_OLED_Module)
- [Waveshare product, SKU 14747](https://www.waveshare.com/product/displays/oled/1.5inch-rgb-oled-module.htm)
- [Solomon Systech SSD1351 datasheet, revision 1.5](https://files.waveshare.com/upload/a/a7/SSD1351-Revision_1.5.pdf)
- [Adafruit SSD1351 initialization reference](https://github.com/adafruit/Adafruit-SSD1351-library/blob/master/Adafruit_SSD1351.cpp)

The driver uses the documented 65k-color RGB565 interface, full 0..127 column
and row windows (15/75), RAM write (5C), and master current (C7). Register
parameters use DC HIGH, independently of the single-byte DC LOW command.
Remap defaults to 74, or 70 for the alternate color order. The per-channel C1
values C8/80/C8 are fixed initialization settings; the diagnostic varies C7.

## Follow-up

The overview/menu preview was verified on the project module on 2026-11-25.
The small status font is less readable than on the grayscale OLED. Keep its
current appearance for now; improving that font is a separate task for both
128x128 OLEDs. This integration does not change font sizes or the UI layout.

The info-notice background is pure black. The previously observed blue row band
was no longer visible in the follow-up hardware test. Startup/shutdown images
use the exact new logo geometry and the supplied cream/amber palette; both
the live controller operation and updated system images were confirmed working.
