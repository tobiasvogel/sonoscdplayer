# ST7735S: SPI driver, diagnostic and 160x128 renderer

Target: **Waveshare 1.8inch LCD Module, SKU 13892**, native 128x160 pixels,
ST7735S controller. The player service still uses the SSD1327; this module is
not yet connected to the player.

## Status

- Controller initialization, 16-bit RGB565 frames, four software rotations,
  configurable panel offsets and RGB/BGR selection.
- Reuse of the existing SPI transport, including 4096-byte transfer chunks,
  mode 0, hardware CE0/CE1 and configurable DC/RESET pins.
- Separate active-high GPIO backlight with explicit pin ownership and on/off
  control. PWM brightness and ambient light control are not included yet.
- Standalone color bars, grid/corner markers, checkerboard, text and black.
- Offline PNG previews and automated tests with fake SPI/GPIO/backlight.
- `LandscapeRenderer` (`sonoscdplayer/ui/renderers/landscape_160x128.py`): draws the common
  semantic screens on a 160x128 color canvas, for the later player binding.

**Confirmed on the project module (18.11.): color order RGB, landscape
rotation 270, offsets X=2/Y=1, DC on BCM22 and RESET on BCM27.** These are the
diagnostic's defaults. The already routed eighth SPI-header
wire, **GPIO9 (physical pin 21)**, can be used for BL once MISO has been released
in the boot configuration. No extra enclosure wire is needed for this option.
There is deliberately **no default backlight pin**: GPIO9 must be selected
explicitly together with `--spi-miso-released`.

Live player data/input binding, service/configuration integration and boot/shutdown
screens follow later. The existing ST7735S profile is not marked driver-ready
by this standalone diagnostic.

## Offline preview (works before any hardware modification)

Run from the repository root:

```sh
PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.st7735s_test \
  --pattern all --preview-dir /tmp/st7735s-preview
```

Pillow (`python3-pil`) is required. This writes five PNGs and reports dimensions,
40960-byte frame size and SHA-256. Without `--gpio --execute`, no SPI or
backlight objects are constructed, and no GPIO/spidev library is imported.
No backlight GPIO assignment is needed for offline previews.

`--rotation 0` and `180` use a logical 128x160 canvas. `90` and `270` use
160x128. PNGs show the logical canvas; the driver rotates the RGB565 pixels
into native memory at transmission time. The diagnostic now defaults to the
confirmed **rotation 270 and RGB color order**, giving a 160x128 canvas.
The low-level `DisplayConfig` retains native rotation 0 by default for callers
constructing native frames directly; it also defaults to RGB.

## Backlight and wiring

The module's **BL input** controls its onboard backlight transistor; it is an
active-high control signal. Connect the module input, not a raw backlight LED,
to the chosen GPIO. Before routing a pin, check it against the existing
buttons, LEDs, sensors and other connections. The diagnostic detects overlaps
with SPI0, DC and RESET, but does not know the enclosure's complete pin map.

Power down and disconnect power before modifying the enclosure or wiring.
Use 3.3 V supply and 3.3 V Pi logic for this test.

| Module | Raspberry Pi | Physical header pin |
|---|---|---|
| VCC | 3.3 V | 1 |
| GND | Ground | 6 |
| DIN | BCM10 / MOSI | 19 |
| CLK | BCM11 / SCLK | 23 |
| CS | BCM8 / CE0 | 24 |
| DC | BCM22, if retaining the revised wiring | 15 |
| RST | BCM27, if retaining the revised wiring | 13 |
| BL | **BCM9, released from SPI MISO** | **21** |

The diagnostic defaults to DC BCM22 and RESET BCM27 as on the project wiring;
pass other values explicitly if the module is wired differently. Use
`--spi-device 1` only when CS is connected to CE1 (BCM7, physical pin 26).
Enable SPI on the Pi if necessary. Hardware requires `python3-spidev` and
the same `RPi.GPIO` binding as the current OLED setup.

Stop any renderer using the same SPI/control pins before connecting or testing
the LCD. After a reboot, stop it again if it was automatically started:

```sh
sudo systemctl stop sonoscdplayer-oled.service
```

### GPIO9 prerequisite

GPIO9 must be released from SPI MISO in the active boot configuration. For
standard SPI0/CE0 use `dtoverlay=spi0-1cs,no_miso` in the active `config.txt`
(`/boot/firmware/config.txt` on current Raspberry Pi OS), then reboot. If an
SPI overlay already exists, adapt that configuration rather than adding a
conflicting one. If CE1 is needed too, the corresponding overlay is
`spi0-2cs,no_miso`. No other SPI0 device may require MISO/readback.

If the preceding e-paper test already used GPIO9 successfully with that boot
configuration, no additional boot change is required. Disconnect the e-paper
BUSY wire before connecting LCD BL to the same wire; never connect both at
once. Change connections only with the Pi powered down and disconnected.

`--spi-miso-released` acknowledges the boot configuration; it does not change
it. After opening SPI, the driver checks that GPIO9 is an input rather than
an SPI alternate function or an output already driven by another owner. It
refuses to configure BL if this check fails. It then configures GPIO9 as an
output initially LOW, before reset or controller commands.

Run the pattern test:

```sh
sudo env PYTHONPATH=src python3 -m sonoscdplayer.hardware.displays.st7735s_test \
  --gpio --execute --backlight-pin 9 --spi-miso-released \
  --pattern all --seconds 5
```

BL is configured LOW after opening
SPI but before resetting or initializing the controller. The driver clears display
RAM to black, enables the panel, and only turns BL HIGH after a complete valid
test frame has been transferred. Exit drives BL LOW before display-off/sleep
and releases only the owned GPIO pins and SPI handle. The electrical BL level
after GPIO cleanup depends on the module's bias resistors and must be checked
on hardware; a LOW write does not guarantee a permanently dark backlight
after returning the pin to input mode. These cleanup guarantees
apply to normal exits and handled exceptions, not power loss or SIGKILL.

Other free backlight pins remain selectable. Omit `--spi-miso-released` when
using an ordinary free GPIO unrelated to SPI; there is no implicit GPIO9
selection. DC and RESET still cannot use SPI0 pins. Backlight is on/off only;
PWM/automatic brightness are later work.

## What to check on hardware

1. Color bars: **red, green, blue, white, cyan, magenta, yellow, black**, left
   to right. RGB is confirmed on the project module and is now the default;
   `--color-order bgr` remains available for explicitly testing other variants.
2. Grid: a continuous white one-pixel border on all four sides. Corners are
   red top-left, green top-right, blue bottom-left and a yellow outline
   bottom-right. No missing, duplicated or wrapped rows/columns.
3. Checkerboard: regular 8x8 black/white squares without transfer corruption.
4. Text: readable model, dimensions and rotation. Use `--rotation` to test
   mounting orientation before changing any defaults.
5. Final image black; observe the backlight during exit and after pin release.
   Record whether the module's bias turns it on again after GPIO cleanup.

Waveshare describes a 128x160 visible area within the controller's 132x162
memory. The provisional offsets are **X=2, Y=1**. Diagnostics accept
`--x-offset 0..4` and `--y-offset 0..2`; these always keep the native frame
within controller RAM. Rotations are applied in software, so offsets are
always expressed in the native orientation. Do not tune these before seeing
the actual border test. Default SPI rate is a conservative 2 MHz, configurable
with `--spi-hz` in the shared transport's 100 kHz..8 MHz range.

RGB color order and the 270-degree landscape mounting are confirmed. Long-term
power/gamma behavior, exact offsets and BL state after cleanup still require
further qualification. SPI success cannot prove that
the panel is connected or that colors and pixels are correct.

## Data and initialization contract

Logical `GraphicFrame` uses `rgb565`, row-major RGB, high byte first:
red `F8 00`, green `07 E0`, blue `00 1F`, white `FF FF`. RGB/BGR selection
changes MADCTL only; it does not change the canonical frame format.

The controller receives one command byte with DC LOW; any register arguments
are transmitted with DC HIGH. This differs from SH1107 command arguments.
Each full-frame write explicitly sends CASET (0x2A), RASET (0x2B), inclusive
endpoints and RAMWR (0x2C), then 40960 bytes. Invalid frames fail before any
bus or backlight write.

Initialization performs hardware reset, software reset with a 150 ms wait,
sleep-out with a 120 ms wait, frame-rate/power configuration, normal polarity,
COLMOD 0x05, fixed native MADCTL (0xC8 for BGR or 0xC0 for RGB), normal mode,
black RAM fill and display-on. Rotation is performed in software. Gamma uses
the controller's reset values in this first increment; there is no calibration.

## Automated validation

```sh
python3 -m pytest tests/hardware/displays -k st7735s
```

Tests cover RGB565 byte order, rotation/corner mapping, frame and offset
validation, command/data separation, exact address windows, blank startup,
backlight sequencing and pin conflicts, partial initialization and cleanup
failures, SPI chunking, all patterns and offline operation without hardware
imports. GPIO9 tests cover explicit opt-in, pinmux rejection before setup,
SPI-before-backlight initialization and cleanup. No physical GPIO is accessed
by these tests.
Renderer tests additionally cover text bounds, scrolling, focus/selection
and progress clamping, using neutral sample screens from
`tests/display_samples.py`.
